# Migrate Tests to `tests/` + pytest, and Expand Coverage — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the test code and fixture data out of the `lqc` package into a top-level `tests/` directory, switch the runner from stdlib `unittest` to `pytest`, and add focused unit/integration tests for the currently-untested core modules.

**Architecture:** Tests live outside the package in `tests/` (discovered by pytest via `testpaths`), reading the committed fixture from `tests/data/cs_test.test_data` through a `tests/conftest.py` fixture. The CS-fixture generator is a developer utility, not a test, so it moves to `scripts/`. `pytest` is declared as a `dev` dependency group (PEP 735, resolved by `uv sync`) rather than a runtime dependency. New tests target the pure-Python parsing/stat machinery (`cs`, `readstat`, `indel`, `mismatch`, `splice`, `utils`) plus the table/HTML/report builders and one tiny indexed-BAM integration case built in-conftest with `pysam`.

**Tech Stack:** Python 3.11, `pytest` (dev group), `pysam` (fixture building only), `numpy`/`pandas`/`matplotlib` (already runtime deps), uv, ruff (transient via `uvx`).
