# uv Package-Management Migration Design

Date: 2026-08-21
Branch: `improvement`

## Problem Statement

The repository is packaged with a legacy `setup.py` (setuptools/distutils shim) that
declares unpinned runtime dependencies, ships the CLI as a raw `bin/lqc` script, and
duplicates the package version in two places (`setup.py` and `bin/lqc`). We are adopting
`uv` as the package manager (`uv sync` for environments, `uvx ruff check` for linting),
which requires a modern `pyproject.toml` and a real console entry point.

## Proposed Solution

Replace `setup.py` with a PEP 621 `pyproject.toml` built by **hatchling**, expose the CLI
through a proper `lqc.cli:main` entry point, and single-source the version in
`lqc/__init__.py`. Pin the development interpreter with `.python-version` and commit the
generated `uv.lock` for reproducibility. Keep `uvx ruff check` transient as agreed.

## Decisions

| Topic | Choice |
| --- | --- |
| Minimum Python | `requires-python = ">=3.11"` |
| Build backend | hatchling |
| CLI entry point | `[project.scripts] lqc = "lqc.cli:main"`; **delete `bin/lqc`** |
| Version | single-source `__version__ = "0.0.5"` in `lqc/__init__.py`; hatch dynamic |
| Dependencies | unpinned (`numpy`, `pandas`, `matplotlib`, `pysam`) — lock pins dev env |
| Ruff | transient via `uvx ruff check`; no dev-dependency |
| Lockfile / interpreter | commit `uv.lock`; add `.python-version` = `3.11` |
| Test runner | keep `unittest` (no pytest) |

## Detailed Design

### `pyproject.toml` (new)

- `[project]`: `name = "lqc"`, dynamic `version`, description, `readme = "README.md"`,
  `license = "GPL-3.0-or-later"` (SPDX), `requires-python = ">=3.11"`,
  `dependencies = ["numpy", "pandas", "matplotlib", "pysam"]`, classifiers carried over
  from `setup.py`, and `[project.scripts] lqc = "lqc.cli:main"`.
- `[build-system]`: `requires = ["hatchling"]`, `build-backend = "hatchling.build"`.
- `[tool.hatch.version]`: `path = "lqc/__init__.py"` (reads `__version__`).
- `[tool.hatch.build.targets.wheel]`: `packages = ["lqc"]` (hatchling includes non-Python
  files under the package by default, so `lqc/template/*.html|*.svg` and
  `lqc/test/*.test_data` ship without extra `package_data` config).
- `[tool.ruff]`: `target-version = "py311"` only (no rule changes).

### `lqc/cli.py` (new) — CLI code moved out of `bin/lqc`

- Move the argument parsing and orchestration currently in `bin/lqc` into
  `def main(argv: list[str] | None = None) -> int`.
- Import from the submodules directly (`lqc.stat`, `lqc.utils`, `lqc.report_table`,
  `lqc.report_figure`, `lqc.report_html`, `lqc.template`) rather than from
  `lqc/__init__.py`, avoiding any import cycle.
- The `--version` flag reads `lqc.__version__` instead of a hardcoded constant.
- Guard the body with `if __name__ == "__main__": sys.exit(main())` so the module is
  also directly runnable.

### `bin/lqc` (deleted)

Removed entirely; `lqc` (installed entry point) and `uv run lqc` are the supported CLI
surfaces.

### `lqc/__init__.py` (modified)

Add `__version__ = "0.0.5"` at the top. No release version bump.

### `setup.py` (deleted)

Fully replaced by `pyproject.toml`.

### `.python-version` (new) and `uv.lock` (generated, committed)

- `.python-version` contains `3.11`.
- `uv.lock` is generated by `uv sync` and committed for reproducible environments.

### `.gitignore` (modified)

Add `.venv/`. (Note: the working tree already has an unrelated pre-existing `.gitignore`
edit — `tmp*` → `tmp/*` — which is left untouched and not part of this change.)

### `README.md` (modified)

Update the Installation section to document both paths:
- end users: `pip install lqc` (unchanged);
- development: `uv sync`, `uvx ruff check`, `uv run python -m unittest lqc.test.test_cs -v`.

### Follow-up doc update

After implementation, refresh `docs/development.md` ("Packaging & versioning" and the
"Transition note") to reflect the landed uv/hatchling/entry-point setup, and remove the
now-resolved `pip install -e .` interim note.

## Preconditions

- `uv` ≥ 0.12 installed (present: 0.12.3).
- Network access for `uv sync` to fetch the Python 3.11 interpreter and dependency wheels
  (numpy/pandas/matplotlib/pysam all ship `cp311` linux x86_64 wheels); `uv build`/`uvx`
  similarly need network on first use.

## Success Criteria

Run in the repository root and confirm each:

1. `uv sync` succeeds and installs the `lqc` entry point into `.venv/`.
2. `uv run lqc --version` prints `lqc 0.0.5`.
3. `uv run python -m unittest lqc.test.test_cs -v` passes.
4. `uv run python -c "import lqc; print(lqc.__version__)"` prints `0.0.5`.
5. `uv build` produces an sdist and a wheel; the wheel contains `lqc/template/*` and the
   `lqc` console script.
6. `uvx ruff check` runs clean on changed files.

## Out of Scope

- No test-runner change (keep `unittest`, no pytest).
- No ruff rule/config expansion, no tree-wide `--fix`.
- No version bump, no new features, no restructuring of `tests/` vs `lqc/test`.
- No commit of unrelated uncommitted changes (`AGENTS.md`, `docs/`, pre-existing
  `.gitignore` edit); only migration files and this spec are committed.
